## 摸鱼阅读器（DeepSeek 伪装版）

- 产物：`index.html`（单文件，无依赖，双击 file:// 直接跑）。
- 目标：页面复刻 DeepSeek 网页对话页，中间消息区渲染本地 TXT 小说，供上班阅读。
- 关键实现：
  - 主色 `#4d6bfe`；侧边栏 264px / `#f9f9f9`；正文列 max-width 700px、16px、行高 1.95。
  - 品牌 logo 用 `logo/deepseek-color.svg`（鲸鱼 mark，24 viewBox）与 `logo/deepseek-text.svg`（字标，131x24 viewBox）**内联**进 HTML：mark 25px 蓝色、字标 104x19；favicon 用鲸鱼转 data URI。页面已不依赖 logo 目录。
  - 章节以「AI 回答」样式渲染：`h1.ch-title` + 段落 + 「本回答由 AI 生成」脚注 + 操作图标行。
  - TXT 解析：`CH_RE` 匹配「第X章/回/卷」等；无章节标记时按 3200 字切节；UTF-8 严格解码失败回落 GBK。
  - 无限上下滚动：`appendNext` / `prependPrev` / `pruneTop`（DOM 只保留约 9 个章节块）。
  - 主页伪装：问候语「👋 嗨！今天想聊些什么？」20px + 输入框居中 **640px**（原来 486 在 1747 宽窗口下显得太小，已改），**输入框靠 DOM 搬移在 `#homeSlot` 与 `#composerWrap` 之间切换**（`syncComposer()`），空输入时发送键为淡蓝 `#b9c4f8`、有字变 `#4d6bfe`。
  - 快捷键：Esc 阅读↔伪装首页（层级：help→目录→书架→设置→模式）、Ctrl+Shift+X 白屏会议纪要、`C` 目录、`B` 书架、Space/→/← 翻页、`[` `]` 跳章、Ctrl+B 侧栏、Ctrl+O 导入、`?` 说明。

### 目录弹窗：大书时行高塌缩（重要 bug）
- 现象：书有 1619 章时，`.toc-item` 高度从 30px 塌到 14px（=只剩 padding 7+7），整页挤成一团。5 章的书完全正常，所以之前没发现。
- 原因：`.toc-list` 是 `display:grid` 且 `grid-auto-rows` 默认 `auto`，条目数远超容器高度时 Chrome 把 auto 行压到只剩 padding。
- 修法：`.toc-item` 给**固定 height:34px**（不要用 min-height，仍会被压），同时 `.toc-list` 加 `grid-auto-rows:min-content`。
- 顺带把目录做宽松：卡片 680→min(920px,100%)、高度 `auto`+`max-height:min(84vh,760px)`（小书自动变矮，5 章时约 254px）、行高 34/行距 4、字号 12.8→13.5、序号 10.5→11.5 且 `tabular-nums`、列间距 4→22、搜索框 31→36 且 `flex:0 1 400px`+关闭按钮 `margin-left:auto`、底部 padding 24。
- 验证：1619 章打开耗时 93ms，搜索 31 条命中、行高恒 34；点条目跳转并关闭正常。
- 教训：**改 UI 后要用接近真实规模的数据（上千章）测**，小样本测不出 grid/flex 的压缩行为。

### 阅读位置重启后跑偏（严重 bug，已修）
- 现象：退出前在第 26 章中部，重新打开变成第 27 章开头。
- 根因：`CURRENT.scroll` 存的是 `chatScroll.scrollTop`——**整个滚动容器的绝对滚动量**。容器里挂着好几章、窗口从哪章开始都会影响它；恢复时 `openChapter(idx)` 只挂 idx/idx+1 两章，窗口起点变了，同一个数字就落到后面某章去了。
- 修法：改存**章内偏移** `offsetInChapter() = scrollTop - S.offsets[idx - winStart]`；恢复时 `scrollTop = base + off`，base 是本章在新容器里的起始偏移（含 `.thread` 的 padding-top，漏掉会整体上移 46px）。
- 恢复后 60ms / 320ms 各再校一次（`refreshOffsets` 后重算 base），消掉布局稳定前的 5~6px 误差，实测 0 误差。
- `saveProgress(true)` 必须**同步写**，原来用 `setTimeout(0)`，在 pagehide 里根本不会执行 → 手快关窗口会丢最后一次位置。
- 顺带修 `percentOf()`：原来固定拿 `offsets[0]/offsets[1]`（窗口前两章），窗口滑动后百分比就错了；改成用当前章的 `offsets[k]/offsets[k+1]`。
- 兼容老数据：旧存档是绝对 scrollTop，恢复时夹到 `本章高度-200`，不会跳到下一章。
- 验证：8 个滚动位置，存[idx, 章内偏移] 与恢复后完全一致（0px 误差）；切书往返、Esc 往返、滚动后 120ms 内关窗口重开，位置都保住了。

### 地址栏伪装成 https://chat.deepseek6.com/a/chat/s/<uuid>
- 组成：① hosts 加 `127.0.0.1 chat.deepseek6.com`；② `cert/` 下自签 CA + 站点证书（SAN=DNS:chat.deepseek6.com，10 年）；③ `certutil -user -addstore -f Root cert\ca.crt` 装进当前用户受信任根（不需要管理员，Chrome/Edge 都读 Windows 证书库）；④ server.py 用 TLS 包 443，80 端口继续提供旧源。
- 关键坑：**系统代理**（HKCU Internet Settings，ProxyEnable=1，ProxyServer=127.0.0.1:7897）会把域名转给代理导致打不开。必须把 `chat.deepseek6.com;*.deepseek6.com` 追加到 `ProxyOverride`。改完 Chrome 立刻生效，Edge 可能要重启。
- Python 侧：`httpd.socket = ctx.wrap_socket(httpd.socket, server_side=True)` 包监听 socket 即可，不用自己写 TLS 循环。
- curl 测 https 要加 `-k`（Git 自带 curl 用自己的 CA bundle，不读 Windows 库），并用 `--noproxy "*"` 绕代理。
- 换 origin = 丢 IndexedDB。做了自动迁移：server 的 `/__migrate` 页面（跑在旧源）读 IndexedDB + localStorage → POST `/__dump` → 跳到新地址；index.html 启动时若本地书架为空就 `GET /__dump` 恢复。成功后写 `migrated.flag`，之后旧地址 301 到新地址。
- 用户实际环境：**Edge，Profile 2**（last_used=Profile 2），旧数据在 `http://172.31.2.61` 源。
- 注意：agent 起的后台进程会在命令结束时被回收（job object），没法替用户常驻服务，必须让用户自己双击 阅读器.bat。

### 打包成单文件 exe（PyInstaller）
